# Question 5 — Operating Systems, Terminals, and Shells

**Format:** Short Answer

---

> Answer in your own words, 1-3 sentences each. Writing it yourself is the point.


**(a)** What is a **kernel**, in plain language? (One or two sentences. No textbook definition copied in; explain it as you understand it.)

**Answer:**
_(A kernel is like the middleman that lets your apps actually use the computer's hardware — it decides which program gets to use the CPU, memory, or storage at any given moment, so everything runs smoothly without programs fighting over the same resources.)_

---

**(b)** A classmate says:

> "I installed WSL, so now I have two completely separate operating systems, Windows and Linux, running side by side, each totally independent."

Is this accurate? Briefly explain why or why not.

**Answer:**
_(Not quite accurate — while WSL does run an actual Linux kernel (in WSL2) alongside Windows, it's not two fully independent, isolated operating systems; they share resources and integrate closely, letting you access Windows files from Linux and vice versa, run Linux commands from a Windows terminal, and even mix tools between the two, which isn't how truly separate, independent systems would behave.)_

---

**(c)** Explain the difference between a **terminal (emulator)** and a **shell**, and give one example of each.

**Answer:**
_(A terminal (emulator) is just the window/interface you type into and see output in, while the shell is the actual program running inside that window that interprets your commands and executes them — for example, Windows Terminal or iTerm2 would be terminal emulators, while bash or zsh would be shells running inside them.)_
